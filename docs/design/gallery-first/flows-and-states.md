# Gallery-first — عقود المسارات والحالات

التاريخ: 1 نوفمبر 2026. النطاق: تصميم تجربة الموبايل والـwireframes فقط.

المرجع: [التصور الأساسي](../../gallery-first-mobile-concept-2026-11-01.md). التنقل المختار هو Gallery / الأشخاص / Discover / الاستوديو، والصور والمجلدات داخل Gallery. هذه الوثيقة تفصّل المسارات حتى لا تختفي وظيفة أثناء الرسم. لا تمثل تنفيذًا أو migration، ولا تثبت نجاح سلوك غير موجود بعد. النص العربي يشرح التصميم، ولا يضيف التزامًا بدعم Arabic/RTL في التطبيق.

## 1. قواعد مشتركة لكل الشاشات

1. الصورة أو الفيديو هما المحتوى الرئيسي. تقدم الفحص، اتصال الكمبيوتر، والموديلات تظهر في سياقها وتفتح التفاصيل عند الطلب.
2. فتح التطبيق أو مجلد أو صورة لا يبدأ تحليلًا، ولا يتطلب ربط الكمبيوتر. التحليل وظيفة منفصلة لها فعل واضح ومصدر معلوم.
3. التصفح مصدره MediaStore ضمن الإذن المتاح. فهرس التحليل يضاف إليه ولا يحدد وحده ما يستطيع المستخدم رؤيته.
4. ظهور الشخص داخل الصورة، الشخص صاحب الهوية، الهوية المصدر في Reface، والوجه المستهدف أدوار مختلفة. لا نملأ دورًا من آخر ضمنيًا.
5. كل مدخل سياقي يفتح الأداة نفسها مع سياق مناسب؛ لا نبني نسخة مستقلة لكل ميزة داخل Gallery وDiscover وStudio.
6. الرجوع يغلق أعلى طبقة أولًا ثم يعود إلى المحتوى والموضع السابق. تحديث البيانات لا يعيد الشبكة إلى بدايتها.
7. لا يعتمد فعل أساسي على السحب أو الضغط المطول وحدهما. يوجد بديل ظاهر للتفاصيل، الأدوات، والقوائم.
8. كل إجراء جماعي يعرض نطاقه وعدده، خصوصًا إذا كان المحدد ظاهرًا في أكثر من صورة أو مجلد.
9. تحميل القوائم أو خطأ اتصال الكمبيوتر لا يُعرض باعتباره مكتبة فارغة. قائمة بلا نتائج فلتر تختلف عن مكتبة بلا ملفات وعن ملفات لا تسمح الصلاحية برؤيتها.
10. قرارات المستخدم، قفل التجميع والإيقاف اليدوي لا تُلغى عند الرجوع أو التحليل أو استعادة الاتصال.

## 2. سياق التنقل الذي يجب أن يبقى محفوظًا

السياق الآتي عقد سلوكي مقترح، وليس أسماء أعمدة جاهزة:

| السياق | ما يلزم حفظه | لماذا |
|---|---|---|
| Gallery | عرض الصور/المجلدات، معرف المجلد، الترتيب والفلتر والموضع | الرجوع لنفس الصورة والمكان |
| مجموعة العارض | مصدر القائمة ومعيارها، الأصل الحالي، موضعه، وقت الفيديو | السحب يتنقل داخل المجموعة الصحيحة |
| لوحة الصورة | مستوى فتح اللوحة، قسمها، الظهور/الشخص المحدد | العودة من ملف الشخص لا تختار شخصًا آخر |
| Discover | نوع البحث، المثال/الفئة، الشخص المقيد، المعايير، الموضع | العودة تحافظ على النتائج والسياق |
| أداة الإنشاء | مصدر الدخول، ملف الإدخال، الهدف المحدد، هوية المصدر، الموديل/الـDataset | الأداة تعرف ما ستعالجه وما ستستخدمه |
| مهمة/نتيجة | معرف المهمة والنتيجة والعلاقات المعروفة ومسار العودة | فتح النتيجة لا يفقد الأصل أو ملف الشخص |

تغيير فلتر يغيّر مجموعة العارض عمدًا؛ الانتقال إلى الشخص لا يغير مجموعة الصورة الأصلية خلفه. لا نفترض حفظ مسودات كل الأدوات عبر إغلاق التطبيق؛ يجب تحديد ما يدعمه كل نموذج قبل التنفيذ.

## 3. F-GAL: البداية، الإذن، وكل الصور

المسار الأساسي: تشغيل التطبيق ← Gallery / الصور ← شبكة زمنية ← مجلد عند اختيار المستخدم ← صورة أو فيديو.

| الحالة | ما يظهر | الفعل التالي | شرط الخروج |
|---|---|---|---|
| أول تشغيل بدون إذن | تعريف قصير بالحاجة للوصول للصور، وفعل طلب الإذن | السماح بالوصول | نتيجة النظام الفعلية |
| إذن كامل | كل الوسائط التي يعرضها النظام ضمن الوصول المتاح | التصفح أو التصفية | لا حاجة لكمبيوتر |
| إذن محدود | الصور المسموح بها، مع عبارة واضحة عن محدودية الوصول | إدارة الصور المسموح بها | إعادة قراءة الصلاحية والقائمة |
| إذن مرفوض | شرح مباشر ومحتوى إعدادات الوصول | المحاولة أو إعدادات النظام حسب الحالة | لا ندخل في حلقة طلب إذن |
| لا توجد ملفات متاحة | حالة فراغ خاصة بالمكتبة المتاحة | إدارة الوصول أو إعادة التحقق | لا نعرض فشل اتصال |
| لا نتائج للفلتر | وصف الفلتر الحالي | مسح الفلتر | لا نطلب Scan لإظهار صور مخفية بفلتر |
| تحميل الفهرس | هيكل شبكة مؤقت أو تقدم بسيط | انتظار أو رجوع | لا يظهر عدد نهائي كاذب |
| الكمبيوتر غير مربوط/غير متصل | شبكة الصور تعمل؛ مؤشر الاتصال ثانوي | ربط عند اختيار وظيفة تحتاجه | الربط ليس حارس دخول للجاليري |
| تغيير الصلاحية أثناء الاستخدام | تحديث العناصر المتاحة وشرح فقد الوصول عند الحاجة | إدارة الوصول | لا حذف تلقائي لسجلات الأشخاص أو النتائج |

قبول F-GAL:

- يبدأ التطبيق بالصور، ولا يفتح Dashboard أو نموذج ربط بدلها.
- فتح تبويب آخر ثم العودة يحفظ عرض Gallery المختار وموضعه؛ بداية تشغيل جديدة تظل الصور وفق التصور.
- صورة غير محللة يمكن فتح أصلها، تكبيره، ومشاركته بالوظائف المدعومة؛ عدم التحليل لا يحجبها.
- لا يُنشأ سجل تحليل جديد لكل مرور على thumbnail؛ طبقة الأصول مستقلة عن طابور Scan.
- إعادة ظهور أصل سبق نقله أو تغير إذنه لا تضاعف الأشخاص أو النتائج تلقائيًا.

## 4. F-FOLDER: المجلدات ومصادر التحليل

المسار: Gallery ← المجلدات ← مجلد فعلي ← شبكة وسائطه ← العارض.

محتوى المجلد: غلاف، اسم، عدد متاح موثوق، شبكة، وفلتر الصور/الفيديو عند الحاجة. الإجراءات الثانوية: تحليل هذا المجلد، إعدادات التحليل، ومدخل إدارة المصادر. لا يُستخدم نفس الشكل أو الاسم لمجلد فعلي ومجموعة هوية أو مجموعة نتائج خاصة.

| الفعل | الأثر المسموح | ما يجب توضيحه |
|---|---|---|
| فتح مجلد | قراءة وسائطه | لا يبدأ الفحص |
| إضافته كمصدر | تحديث مصادر التحليل | ما سيُحلل ومن أي وقت/نوع وفق الضوابط الموجودة |
| بدء التحليل | استكمال خطوة الاتصال/الجاهزية ثم إدراجه بالطابور | العدد إن أمكن؛ الصور/الفيديو؛ تصنيف real/illustrated |
| إيقاف الفحص | إيقاف مدعوم مع حفظ التقدم | التصفح يظل متاحًا |
| إزالة مصدر من إعدادات التحليل | تعديل إعدادات مصدر الفحص | يجب تحديد أثره على الفهرس قبل التنفيذ؛ لا تسمية مبهمة توحي بحذف ملفات |
| فتح النتائج الخاصة | مجموعة داخل التطبيق تحمل تسمية واضحة | لا تصبح مجلد MediaStore أو صورًا عامة بمجرد عرضها |

تبقى ضوابط الصور، كشف الأجسام، حجم الصور، عينات الفيديو، وتصنيف المجلد كصور حقيقية أو شخصيات مرسومة متاحة. لا نعمم نقل/حذف/إعادة تسمية كل ملفات الهاتف من مجرد وجود Folder view؛ أي فعل ملفات جديد يحتاج نطاقًا ودعمًا محددين.

قبول F-FOLDER: الرجوع من العارض يعيد نفس المجلد والموضع؛ فتحه بلا كمبيوتر يعمل؛ بدء Scan لا يغير صلاحية الملفات ولا ينقلها؛ تغيير إعدادات المصدر لا يمحو قرارات الهوية.

## 5. F-PHOTO: فتح الصورة ثم السحب لأعلى

المسار: شبكة ← صورة بكامل المساحة المتاحة ← سحب لأعلى من منطقة التفاصيل أو زر تفاصيل ← لوحة الصورة.

طبقات العارض: الصورة، أدوات العرض، لوحة التفاصيل، ثم اختيار/تصحيح أو أداة مستقلة عند الحاجة. علامات الوجوه/الأجسام اختيارية وليست دائمة فوق الصورة.

| التفاعل | السلوك |
|---|---|
| سحب أفقي عند عدم التكبير | التالي/السابق داخل نفس المجلد أو الشخص أو نتائج البحث |
| Pinch / double tap | تكبير وتحريك الصورة؛ لا يطلق الانتقال الأفقي أو اللوحة عرضًا |
| تفاصيل أو سحب لأعلى من موضعه | فتح لوحة الصورة؛ الإيماءة ليست البديل الوحيد |
| سحب لأسفل داخل لوحة | تمرير محتواها أولًا؛ عند أعلاها يمكن تصغيرها/إغلاقها |
| Back مع قائمة/لوحة مفتوحة | إغلاق الطبقة العليا أولًا |
| Back من العارض | العودة للشبكة وموضع الأصل |
| فتح شخص ثم الرجوع | نفس الصورة، ومستوى اللوحة، والشخص المحدد |

ترتيب اللوحة: الأشخاص هنا ← سياق الشخص/الظهور المختار ← الأدوات الملائمة ← موديلاته المرتبطة ← تعديلات الصورة المرتبطة عندما تتوفر العلاقة ← معلومات الملف والتحليل. لا يلزم عرض أقسام فارغة كبيرة؛ يظهر المدخل المناسب في موضعه.

### الأشخاص داخل الصورة

| الحالة | العرض | الفعل |
|---|---|---|
| معروف واحد | غلاف واسم | الضغط يفتح الشخص؛ فعل منفصل للتصحيح |
| عدة معروفين | قائمة واضحة لكل الأشخاص المميزين | الضغط على الاسم/الغلاف يفتح الملف؛ تحديد للشخص المستهدف بالسياق له affordance منفصلة |
| مجهول | crop مناسب و«مين ده؟» | تعيين لشخص قائم أو إنشاء شخص |
| جسم بلا وجه | معاينة الجسم ومعرفته إن كانت معلومة | اختيار الجسم/تصحيح الربط؛ لا اختلاق وجه |
| شخص له أكثر من اكتشاف في الأصل | مدخل شخص واحد، وإمكانية اختيار الظهور المحدد للأداة | أدوات الوجه/الجسم تستخدم occurrence محددًا لا الشخص وحده |
| لم تُحلل | «اعرف مين في الصورة» وحالة التحليل | بدء تحليل صريح |
| تحليل جارٍ | تقدم قابل للفتح | الاستمرار في مشاهدة الصورة أو فتح النشاط |
| التحليل انتهى بلا وجوه/أجسام | «لم يُعثر على أشخاص في التحليل الحالي» | إعادة اكتشاف مدعومة أو تفاصيل؛ لا استخدام «لا يوجد أشخاص» كحقيقة قطعية |
| فشل التحليل | السبب المفيد وحالة المحاولة | إعادة المحاولة أو فتح تفاصيل النشاط |

الصورة الجماعية تبدأ بلا افتراض شخص نشط؛ يختار المستخدم الشخص/الظهور عند إجراء يحتاجه. الضغط على الشخص للزيارة يظل منفصلًا عن اختيار الهدف. يمكن فتح السياق عبر «أدوات لهذا الشخص» أو علامة تحديد واضحة، مع إبراز الجسم/الوجه المقصود مؤقتًا.

### ربط الموديلات من الصورة

- بعد اختيار شخص تظهر موديلات LoRA المرتبطة به فقط، لا كل الموديلات الموجودة في الصورة ولا موديلات أشخاص آخرين.
- وجود أكثر من موديل يعرض الاختيار؛ لا اختيار عشوائي أو مبني على تشابه الاسم.
- عدم وجود موديل يعرض «إعداد تدريب لهذا الشخص» بعد تثبيت هويته وتحقق شروط بيانات التدريب.
- الشخص المجهول يبدأ بالتعيين/إنشاء الهوية، ثم الوصول للتدريب. لا ننشئ model owner مجهولًا وراء الكواليس.
- مهمة تدريب جارية تظهر كمهمة، ولا تعرض زر استخدام موديل قبل الاستيراد المحلي الناجح.
- موديل DFM المتاح على الكمبيوتر لا يُنسب لشخص إلا بعلاقة صريحة تُبنى لاحقًا؛ المحرك المشترك أو embedding model ليس موديل هذا الشخص.
- «استخدام الموديل» يفتح الأداة المدعومة لذلك النوع. لا يوحي أن LoRA هو مدخل جاهز لأي محرك Reface.

قبول F-PHOTO:

- كل gesture له بديل واضح؛ التكبير لا يحرك الصور أو يفتح اللوحة بالخطأ.
- بناء «الأشخاص هنا» يعتمد MediaDetections؛ الوجوه المكررة المرتبطة بسجل سابق لا تختفي.
- الأداة تستلم الأصل والهدف المحدد بالفعل. إن لم يُحدد الهدف، تطلبه بوضوح.
- الضغط على شخص لا يعدّل هويته. التعيين والتصحيح أفعال مستقلة.
- العودة من شخص أو موديل أو أداة تُبقي صورة الدخول وسياقها.

## 6. F-VIDEO: نفس العارض مع زمن واضح

المشغل يحتفظ بالتشغيل والإيقاف والتقديم والموضع. اللوحة تميز «في هذه اللقطة» عن «ظهروا في الفيديو»؛ لا تجمع وجوهًا من أوقات مختلفة وتوحي أنهم في نفس الإطار. فتح crop من نتيجة أو ملف شخص يرجع إلى timestamp معلوم، وإن كان غير معلوم يُعرض الفيديو دون ادعاء دقة زمنية.

اختيار هدف Reface للفيديو يتم بالهويات المرجعية والأوقات/trim المدعومة. مربعات الوجه الثابتة للصورة لا تُعامل كاختيار هدف صالح لكل الفيديو. تبقى قيود legacy مرئية في موضعها. أدوات group poses وequipment الخاصة بالصور لا تظهر كأنها تعمل على الفيديو. عند عدم دعم التصدير/المقارنة لوسيط معين يُعرض الفعل المناسب للنوع الفعلي فقط.

قبول F-VIDEO: تبديل الوقت يحدّث السياق دون إسقاط هوية المصدر المختارة؛ الرجوع يحفظ وقت المشاهدة؛ اختيار reference لا يتحول إلى اختيار كل الوجوه تلقائيًا؛ إعداد trim يظل جزءًا صريحًا من العملية.

## 7. F-PERSON: الشخص يبدأ بوسائطه الأصلية

المسار: People/Characters أو لوحة الصورة ← ملف الشخص ← تبويب الوسائط افتراضيًا.

| سطح الملف | المحتوى | الفعل الأساسي |
|---|---|---|
| رأس الشخص | الغلاف والاسم وأدوات سريعة قليلة | زيارة الوسائط/أداة سياقية |
| الوسائط | الصور والفيديوهات الأصلية التي يظهر فيها | فتح العارض ضمن مجموعة الشخص |
| الهوية | الوجوه، الأجسام، مجموعات الوجه المرجعية، العلامات | إضافة/تصحيح/اختيار هوية |
| الموديلات | LoRAs، Datasets، المهام والنتائج المرتبطة بالروابط المتاحة | فتح موديل أو إعداد تدريب |
| الاقتراحات | تنبيه وعدد موثوق ومدخل ثابت من الأدوات | مراجعة مرتبطة بالشخص |
| أدوات الشخص | تنظيم، تصحيح/مطابقة، صور/تصدير، تفاصيل، حذف | تنفيذ العملية داخل نطاق واضح |

وظائف الأدوات التي يجب الاحتفاظ بها: الاسم والغلاف، أفضل غلاف، favorite/pin/hide، مجموعات الهوية، قفل التجميع، إضافة وجوه، تعيين/إزالة تعيين، رفض، تجاهل، حذف اكتشاف، دمج وفصل وتمييز شخصين، Person/Character، نقل الملفات الفعلية مع preview، تصدير التدريب وتفاصيل الجودة/الاكتشاف. تعميم التحديد المتعدد يجب ألا يفقد العمليات القائمة أو يضيف عمليات غير مدعومة.

الحالات: الشخص بلا اسم، شخص بلا وسائط أصلية متاحة مع وجود crops، لا نتائج للفلتر، وجوه موجودة بلا موديل، موديل محفوظ والكمبيوتر غير متصل، شخص حُذف أثناء فتحه، Person مقابل Character. أدوات Studio التي تتطلب أشخاصًا حقيقيين لا تظهر صالحة للشخصيات المرسومة.

قبول F-PERSON: الفتح الافتراضي لا يبدأ بشبكة crops؛ زيارة وجه أو جسم ما زالت ممكنة؛ الانتقال People↔Characters يحفظ البحث والترتيب لكل سياقه؛ الملف بلا أصول متاحة لا يُحذف تلقائيًا؛ نتائج/موديلات بلا مالك بعد عملية قديمة لا تُنسب بالاسم.

## 8. F-REFACE: هوية المصدر منفصلة عن الوجه المستهدف

الأدوار المرئية في كل مراجعة للعملية:

- **الصورة/الفيديو الهدف:** الملف الذي ستنشأ منه النتيجة.
- **الوجه/الشخص المستهدف داخله:** ما سيُعدل داخل الملف، باستخدام target boxes للصور أو reference identities للفيديو بحسب المحرك.
- **هوية المصدر:** شخص أو مجموعة وجوه حقيقية محفوظة أو المصدر الآخر الذي تدعمه الأداة؛ DFM مسار منفصل عند توفره.

| نقطة الدخول | ما يملأ تلقائيًا | ما يظل مطلوبًا |
|---|---|---|
| من صورة مفتوحة | الملف الهدف | هدف داخلها إن لم يُحدد؛ ثم هوية المصدر |
| من شخص محدد داخل الصورة | الملف الهدف والظهور المستهدف بعد اختيار صريح | هوية المصدر؛ لا نجعل الشخص نفسه المصدر تلقائيًا |
| «استخدم هويته» من ملف الشخص | الشخص كهوية مصدر | اختيار ملف الهدف ثم وجوهه/هوياته المستهدفة |
| من Studio | لا أدوار مفترضة | اختيار المصدر والهدف بوضوح |
| من ملف خارجي | الملف في دوره الذي اختاره المستخدم | بقية الأدوار؛ لا إدراجه في التحليل بلا فعل |

المسار: تحديد الملف/الدور ← اختيار الهدف ← اختيار هوية المصدر/مجموعتها ← إعدادات الجودة والمحرك والـtrim عند انطباقه ← مراجعة مختصرة بالأدوار ← بدء المهمة ← النشاط ← النتيجة والمقارنة.

الحالات المطلوبة: لا وجه صالح في المصدر، لا اكتشاف في الهدف، الحاجة لتحليل الهدف، اختلاف embedding model، identity set أصبحت غير صالحة بعد تعديل الأشخاص، أكثر من وجه، أكثر من reference بالفيديو، محرك/DFM غير متاح، انقطاع أثناء الرفع، إعداد لا ينطبق على legacy، عدم توفر الأصل.

قبول F-REFACE: لا تبدأ مهمة بدور مفقود؛ مراجعة العملية تسمي المصدر والهدف؛ المصادر Files/Gallery ومجموعات الهوية تبقى متاحة؛ المدخل السياقي لا يفقد original أو target choice؛ لا يظهر LoRA كمصدر Reface مباشر لمجرد أنه تابع للشخص. تبقى آلية identity augmentation من portraits المتحققة متاحة في موضعها الصحيح.

## 9. F-TRAIN: Dataset ← تدريب ← موديل جاهز

المسار: شخص ← الموديلات ← إعداد Dataset ← اختيار المصادر ← إعدادات البناء ← مهمة بناء ← Dataset محلي ← مراجعة الصور والكابتشن/include-exclude ← تدريب بمعلماته ← مهمة تدريب ← استيراد موديل متحقق ← صفحة الموديل.

| المرحلة | الحالة وما يظهر | الفعل التالي |
|---|---|---|
| اختيار الشخص | هوية مالك معلومة ومرجع وجه صالح | اختيار الصور/الفيديوهات المدعومة |
| اختيار المصادر | معاينات ومصادر معلومة، وإطار الشخص المقصود عند الحاجة | إعداد الـDataset |
| بناء Dataset | تقدم ومهمة في النشاط | فتحه بعد الاستيراد المحلي |
| مراجعة Dataset | الصور والكابتشن والمشمول/المستبعد وtrigger/repeats | تعديل/تصدير ZIP/بدء تدريب |
| تدريب | queued/running/paused/failed مع تقدم ذي معنى | الإيقاف/الاستئناف المدعوم/تفاصيل الخطأ |
| تنزيل/تحقق/حفظ | الموديل ليس جاهزًا بعد | انتظار أو معالجة خطأ التخزين/النقل |
| موديل محلي جاهز | المالك والنوع والاسم المتاح وtrigger وحالة الملف | توليد/تصدير/مشاركة بحسب الدعم |
| ملف الموديل مفقود | السجل موجود والوزن غير متاح | معالجة الفقد؛ لا زر استخدام صالح |

صورة جماعية تدخل Dataset لشخص معلوم، ولا تعني تدريب كل من فيها. اختيار الأصل الواحد يمكن أن يبدأ إعداد Dataset، لكنه ليس وعدًا بأن صورة واحدة تحقق شروط التدريب. لا نحفظ target person في دور مالك training من غير تأكيد هذا السياق.

تفاصيل الموديل المقترحة: مالكه، نوعه، اسمه المميز، تاريخ الإنشاء، Dataset المصدر عندما تُعرف العلاقة، المهمة المنشئة، الملف وجاهزيته، trigger وإعداداته ذات الصلة، النتائج المرتبطة. الاسم/الإصدار وعلاقة dataset ليست كلها حقولًا حالية؛ يلزم بناء العلاقة قبل عرضها كحقيقة.

توقف التدريب لا يعد باستئناف أي خطوة؛ تُشرح نقطة الاستئناف الفعلية المدعومة (epoch checkpoint). فشل أو فقد المهمة لا ينشئ موديلًا جاهزًا وهميًا. بقاء بطاقة مهمة ضمن ملف الشخص لا يعني وجود وزن مدرب قابل للاستخدام.

قبول F-TRAIN: مالك الـDataset والموديل متسق؛ مراجعة include/exclude/caption والتصدير لا تضيع؛ استيراد model محلي يتم بعد التحقق؛ تعدد الموديلات للشخص واضح؛ الشخص الواحد لا يختزل في وزن واحد؛ لا خلط بين IdentitySet وLoRA وbase checkpoint وDFM.

## 10. F-GENERATE وF-RESULT: من الموديل للنتيجة ثم الأصل

المسار: موديل جاهز من الشخص/Studio/لوحة الصورة ← توليد بأداة LoRA ومعلماتها ومراجعها ← مراجعة مدخلات ← مهمة ← نتيجة خاصة محلية.

فتح التوليد من موديل يحدد ذلك الموديل والشخص المالك. فتحه من صورة يعطي الصورة دور reference فقط إذا اختار المستخدم ذلك؛ وجود الصورة خلف الأداة لا يجعلها reference ولا هدفًا تلقائيًا. تحافظ الأداة على prompt/negative prompt ومعلمات التوليد المدعومة والمراجع وأوضاعها وmulti-angle.

النتيجة: صورة/فيديو بمقاس مناسب، ومقارنة/قبل وبعد عندما يكون لها مصدر حقيقي محفوظ، ومداخل للأصل والأداة/الشخص/الموديل بالعلاقات المتاحة، favorite، مشاركة، حفظ للمعرض العام، وحذف بالنطاق الحقيقي.

| حالة العلاقة | العرض |
|---|---|
| أصل حي معروف ونسخة مصدر خاصة | فتح الأصل والمقارنة مع تسمية النسخة عند استخدامها |
| الأصل غير متاح والنسخة الخاصة موجودة | توضيح أن المعروض نسخة المصدر المحفوظة |
| توليد من نص بلا أصل | نتيجة توليد؛ لا زر «الصورة الأصلية» مصطنع |
| نتيجة قديمة بلا source/model link | «مصدر غير مرتبط» أو بيانات معروفة فقط؛ لا ربط بالاسم أو التشابه |
| الموديل محذوف بعد التوليد | تحتفظ النتيجة بتاريخها المعروف مع حالة أن الوزن غير متاح |
| الشخص محذوف/انفصل | لا تحويل آلي لمالك جديد من الاسم؛ يلزم policy صريحة |
| نتيجة لم يُتحقق منها/لم تلتزم محليًا | حالة استيراد، لا نتيجة مكتملة |

قبول F-RESULT: النتيجة تظل خاصة حتى حفظ/تصدير صريح؛ مشاركة النتيجة لا تعني نقل الأصل؛ لا ضياع للروابط المعروفة بعد navigation؛ العلاقات القديمة غير المعروفة لا تُخترع؛ الفحص والتحقق والحفظ المحلي تسبق ACK وتنظيف scratch على الكمبيوتر.

## 11. F-DISCOVER: بحث بصري له مثال وهدف واضحان

مداخل Discover: تبويب رئيسي، ابحث عن مشابه من جسم في صورة، أدوات مجموعة في صورة، قسم الهوية/الأجسام/العلامات لشخص، وفئة محفوظة.

| العائلة | المدخل/المعيار | الناتج | حدود لا يخفيها الرسم |
|---|---|---|---|
| أجسام وposes | مثال بصري أو Tier-A chips أو pose محفوظ | أجسام/أصول مع الجسم المقصود | التغطية والجودة تؤثر؛ لا نتائج لا تعني عدم وجود الحركة |
| ملابس/ألوان | outfit exemplar أو لون أو فئة محفوظة | crops مرتبطة بالأصل | وصف ألوان/تشابه مدعوم؛ لا بحث دلالي غير منفذ |
| Group poses | صورة مجموعة، مثال/اسم حركة وهندسة المجموعة | صور مجموعات كاملة | photos only، 2–6، كل الأعضاء المقاسين؛ لا subset من زحام |
| Equipment | label/مثال والمعايير المدعومة | صور/أجسام مع المعدة | association اقتراح؛ المالك قد يظل shared |
| علامة/وشم | علامة محفوظة أو رسمها على جسم شخص | تطابقات قوية/محتملة للمراجعة | لا تعيين هوية تلقائي من اقتراح |
| مناطق الجسم | جسم مثال/بحث chest أو lower-body | تشابه مدعوم مع crop/الأصل | clusters اختيارية وتجريبية مغلقة افتراضيًا |

التفاعل: مدخل ← اختيار مثال/فئة ومعيار مدعوم ← نتائج مع تحديد الجسم/المجموعة المقصودة ← فتح الأصل بنفس العارض ← زيارة شخص أو تصحيح ← رجوع لنفس النتائج والمعايير والموضع.

يظل حفظ فئة pose/outfit وتعديل اسمها واستبعاد عناصرها وحذفها متاحًا. الاستبعاد يُحفظ كقرار، ولا يعاد ضم الجسم عند إعادة scoring. equipment تدعم كشفًا وتصحيح label/owner ورفضًا وإضافة يدوية مع الحفاظ على التصحيح عند إعادة الكشف. العلامة ترسم على أصل مناسب وتُحفظ لشخص؛ نتائج التطابق تعرض الفعلين المعروفين نعم/لا والتردد حيث يدعمه مسار المراجعة.

الحالات: فهرس قيد البناء، لا body descriptor صالح، لا مثال محفوظ، لا نتائج، body/reference مفقود، أصل محذوف وcrop موجود، optional capability غير متاحة، calibration غير مقاسة، فتح تجريبي مغلق. garment tags الخام لا تظهر كفلاتر مؤكدة؛ لا تتحول feature backend تلقائيًا إلى منتج جاهز.

قبول F-DISCOVER: كل نتيجة لها مرجع الأصل والجسم المقصود؛ الرجوع لا يمسح query؛ الشخص المقيد يظل واضحًا؛ group/equipment لا تعمم على الفيديو؛ أدوات التصحيح لا تندمج مع مجرد فتح الصورة؛ لا تكرار متنافس لنفس مكتبة الأدوات داخل عدة تبويبات.

## 12. F-REVIEW: تصحيح الهوية ثم احترام القرار

المداخل: الأشخاص ← المراجعة، غير مصنف، تنبيه الشخص، اقتراح في الصورة، نتائج علامة/تشابه مرتبطة بهوية. Quick Review يبقى سريعًا، والقوائم المتقدمة تبقى قابلة للوصول.

| السؤال/الفعل | الأثر الذي يجب تمييزه |
|---|---|
| نعم، هذا الشخص | تعيين/قبول الاقتراح في نطاقه |
| لا، ليس هذا الشخص | رفض هذا الربط وتذكره عند regroup/rescan |
| غير متأكد | snooze؛ لا يتحول إلى رفض أو قبول |
| إنشاء شخص | إنشاء هوية من المحدد فقط |
| تعيين لشخص آخر | اختيار مالك واضح؛ تصحيح هذا الربط الصريح |
| تجاهل من المراجعة | إبعاده عن التجميع/الأسئلة كما يدعم التطبيق؛ لا حذف ملف |
| حذف اكتشاف | حذف السجل/crop مع suppression المدعومة؛ لا حذف أصل الصورة |
| هذان شخصان مختلفان | distinct relation تُحترم لاحقًا |
| دمج | اختيار survivor ومراجعة الأثر على كل الروابط |
| فصل | اختيار الوجوه المقصودة والهوية الجديدة؛ أثر الموديلات لا يُفترض |

Quick Review يعرض سبب الاقتراح والمعاينات اللازمة والأصل/crop مع التكبير وLens. فتح صورة لا يجيب السؤال، والتكبير لا يحفظ اسمًا أو تعيينًا. يبقى draft الاسم أثناء المعاينة والرجوع وفق السلوك القائم.

قبول F-REVIEW: سؤال نعم/لا/غير متأكد له نتائج منفصلة؛ الرفض يظل بعد تحليل جديد؛ grouping lock محفوظ؛ التحديد الجماعي يعرض نطاقه؛ قائمة review المخزنة تعمل offline؛ نتائج مستجدة قد تظهر بعد إعادة التجميع دون إلغاء تصحيح سابق.

## 13. F-ACTIVITY: الفحص والمهام والسجل

النشاط مدخل عام واضح عند وجود عمل، ومتاح من Studio ومن المهمة. صفوف الفحص ومهام الإنشاء تلتقي في مركز واحد، لكن تحتفظ كل منها بنوعها وحالاتها الفعلية؛ لا نحول كل شيء إلى حالة Progress واحدة مبهمة.

| المرحلة | وصف المستخدم | الأفعال بحسب الدعم |
|---|---|---|
| تحضير/تجزئة/رفع | يجري تجهيز أو إرسال المدخلات | إيقاف/إلغاء فقط حيث مدعوم مع حفظ التقدم |
| queued | في الطابور مع السبب المفيد | إيقاف أو فتح التفاصيل |
| running | المرحلة الجارية والتقدم/ETA عند توفره | إيقاف مدعوم وتفاصيل |
| paused by user | متوقف بطلب المستخدم | استئناف صريح؛ لا استئناف عند رجوع الاتصال تلقائيًا |
| waiting for PC/network | توقف بسبب الاتصال | اتصال/إعادة تحقق ثم الاستئناف المدعوم |
| downloading/verifying/importing | النتيجة تنتقل/تُراجع/تُحفظ | عدم عرض completed قبل الالتزام المحلي |
| completed | النتيجة أو artifact المحلي متاح | فتح النتيجة/الـDataset/الموديل |
| failed | خطأ ورسالة قابلة للتصرف | محاولة/استئناف حسب نوع المهمة، دون إنشاء نتائج مكررة |
| lost/expired | الكمبيوتر لم يعد يحتفظ بالمهمة | توضيح الفقد وخيارات البدء المدعومة |

الأفعال الحالية pause/resume/remove والإدارة والسجل وETA والموارد تبقى متاحة. «إزالة من السجل» ليست «إلغاء المهمة» ولا «حذف النتيجة»؛ كل فعل يحمل اسمه وأثره. لا نعد بزر cancel أو إعادة ترتيب لطابور لا يدعمه التنفيذ الحالي.

قبول F-ACTIVITY: network change لا يفقد stable job id؛ إعادة المحاولة لا تكرر الاستيراد؛ يحترم owned job/server identity؛ manual pause لا تزول؛ لا ACK قبل التحقق والحفظ؛ اختفاء تبويب Jobs من الشريط لا يخفي السجل أو أدواته.

## 14. F-OFFLINE وF-MISSING: الاتصال والأصل المفقود

| الحالة | ما يظل متاحًا | المعالجة السياقية |
|---|---|---|
| PC غير مربوط | Gallery، صور الهاتف، الأشخاص/المراجعة/النتائج المحفوظة | الربط عند بدء وظيفة تحتاجه |
| PC غير متصل | نفس المحتوى المحلي؛ موديلات محفوظة للعرض | عرض سبب توقف التحليل/التوليد ومدخل اتصال |
| endpoint تغير | لا فقد للتصفح أو jobs المحلية | اكتشاف/استعادة بعد التحقق من pin وserver ID |
| token revoked أو هوية خادم مختلفة | البيانات المحلية قائمة | إعادة ربط صريح؛ لا إرسال tokens لخادم مختلف |
| محرك غير متاح | بقية الوظائف قائمة | الأداة تشرح القدرة المطلوبة وخياراتها المدعومة |
| الأصل فقد الإذن | crop/نتيجة/نسخة مصدر خاصة إن وجدت | إدارة الوصول وإعادة التحقق؛ تسمية البديل بدقة |
| الأصل حُذف | السجل/المعاينات المعروفة حسب المتاح | لا نتيجة أصل مزيفة، ولا حذف الشخص تلقائيًا |
| نقل الأصل | تسوية asset reference بعد العملية المدعومة | لا إنشاء الشخص من جديد أو مضاعفة الوسائط |
| الملف الخاص نفسه مفقود | بياناته المعروفة مع missing state | لا زر تشغيل/مشاركة يوحي أن الملف متاح |
| امتلاء التخزين | إيقاف الالتزام بالنتيجة بأمان مع رسالة محددة | إدارة التخزين/إعادة المحاولة؛ لا ACK مبكر |

تمييز الصور الأصلية، crops، ونسخة مصدر خاصة ضروري في label والمعاينة وLens. Lens يرسل الصورة المختارة فقط بعد ضغط صريح؛ فتح أو توسيع صورة لا يرسلها وحده. إذا استُخدم crop fallback، يتغير label بدل الادعاء أنه original.

قبول F-OFFLINE: لا شاشة اتصال تقطع Gallery؛ لا حذف records عند مؤقت permission failure؛ لا تحليل أو تعيين من مجرد إعادة الاتصال؛ لا خلط بين نسخة محفوظة والأصل الحي؛ privacy/app lock تظل مطبقة على كل viewers وshare flows الحالية.

## 15. F-DESTRUCTIVE: نطاق الأفعال والتأكيدات

التأكيد هنا جزء من تصميم الفعل الخطير ونطاقه، وليس طلب موافقة جديد من المستخدم على عمل التصميم.

| الفعل | ما يجب تسميته قبل التأكيد | ما لا يجوز الوعد به |
|---|---|---|
| حذف شخص | حذف الهوية وأثره على الوجوه/الأجسام والهوية المحفوظة والعلامات والروابط | أنه يحذف صور الهاتف، أو أن كل بياناته قابلة للتراجع |
| حذف وجه/اكتشاف | حذف سجل الاكتشاف/crop وحفظ suppression المدعومة | حذف الأصل أو مجرد رفض تطابق |
| رفض تطابق | فصل/رفض هذا الربط وتذكره | حذف crop أو أصل |
| حذف نتيجة | artifact الذي سيحذف فعلًا، ونسخة المصدر الخاصة المصاحبة | حوار «حذف صورة» إذا العملية ستمحو Dataset أو LoRA |
| حذف Dataset | عناصره الخاصة/كابتشنه والعلاقات المتأثرة | حذف أصول الهاتف التي كانت مصدره |
| حذف موديل | وزن الموديل المحلي والروابط التي ستفقد توفره | حذف كل النتائج التاريخية تلقائيًا |
| دمج شخصين | من سيبقى، من سيحذف، scope المراجع/الموديلات/العلامات | undo شامل أو انتقال كل artifact إن لم يُنفذ |
| نقل أصول | معاينة الملفات والوجهة والتعارضات وطلب النظام المدعوم | نقل افتراضي بمجرد تنظيم الأشخاص |
| تنظيف تخزين | الملفات الخاصة غير المشار إليها والكمية | حذف staged inputs لازمة لمهام paused/failed |
| Restore | استبدال المكتبة المحلية بالنسخة، وما لن يأتي معها | دمج آمن تلقائي أو استعادة كل صور الهاتف |

قبل تنفيذ إعادة التصميم يلزم policy منفصلة لدمج/فصل/حذف الهوية وتأثيره على provenance، وإدارة فقد الملف. لا تؤجل هذه السياسة إلى تعديل واجهة بعد migration.

قبول F-DESTRUCTIVE: أسماء الأفعال تعكس النطاق؛ preview النقل موجود؛ لا زر undo غير مدعوم؛ حذف الهوية لا يُسمى حذف صور؛ حذف artifact يشير إلى dataset/model عند انطباقه؛ أي confirmation يعرض أثرًا يمكن التحقق منه من التنفيذ.

## 16. F-BACKUP: النسخ والاستعادة والخصوصية

المسار: إعدادات ← Backup ← اختيار التصدير/الاستعادة ← معلومات النطاق ← تقدم ← نتيجة واضحة.

- النسخة الحالية تحفظ فهرس المكتبة والتصحيحات والهويات والمراجع والأصول الخاصة المشتقة والموديلات/النتائج التي يشملها نظام النسخ الحالي؛ لا تعني نسخ كل أصول MediaStore.
- التصدير المشفر هو المسار الافتراضي الحالي. شاشة المشاركة لا تترك plaintext مؤقتًا بلا إدارة التنظيف الحالية.
- معلومات backup تشمل قابلية القراءة والإصدار/التوافق والنطاق، ثم تأكيد استبدال المكتبة عند Restore. لا نخلط Inspect وRestore.
- لا تنتقل servers/tokens وسجلات رفع مؤقتة كأنها اتصال صالح على جهاز آخر؛ إعادة الربط منفصلة.
- أثناء restore/maintenance تُوقف الكتابات المتعارضة وفق الآلية القائمة. بعد الانتهاء لا يبدأ Scan متوقف يدويًا تلقائيًا.
- فشل كلمة المرور/التلف/نقص التخزين/إصدار أحدث حالات منفصلة لها فعل مناسب. إلغاء share لا يُسمى backup تم تسليمه.
- App lock والـprivate viewers والخلفية والبطارية والتخزين تظل في إعدادات واضحة، مع روابط سياقية عند تأثيرها على مهمة فعلية.

قبول F-BACKUP: النص يميز الفهرس/الأصول الخاصة عن صور الهاتف الأصلية؛ restore استبدال صريح لا merge؛ لا تتسرب credentials؛ تقدم واقعي، وإلغاء وفشل واضحان؛ لا تغيير تلقائي لقرارات الإيقاف أو المجموعة التجريبية.

## 18. فجوات التنفيذ التي يجب ألا تخفيها الـwireframes

هذه نتائج فحص المصدر وليست أخطاء أُصلحت في هذه المرحلة:

1. **التصفح قبل التحليل:** Library الحالية مبنية على media في DB، لا كل أصول الهاتف. Gallery الجديدة تحتاج طبقة تصفح مستقلة وعلاقة ثابتة مع analyzed media.
2. **الـprovenance:** Results تحفظ personId ومسار أصل خاص، دون mediaId/loraId/datasetId. Loras لا تحمل datasetId/name/version صريحة، وDatasetItems لا تحمل original asset pointer. لا تعرض history أو links دقيقة قبل بنائها وترحيل المعلوم فقط.
3. **دمج الأشخاص:** mergePeople الحالية تنقل faces/bodies/IdentitySets وبعض قرارات التصحيح ثم تحذف source person، لكنها لا تعيد ربط Loras/Datasets/Jobs/Results بالشخص الباقي. BodyMarks مرتبطة بحذف cascade. يلزم policy وتنفيذ يحافظان على المطلوب قبل وعد «كل موديلاته وعلاماته تنتقل».
4. **حذف النتيجة:** deleteResult الحالية تحذف same-ID LoRA/Dataset وملفات الـDataset أيضًا عند انطباق ذلك. لا يُرسم تأكيد عام يوحي بأنه image-only delete.
5. **DFM:** قائمة قدرات الكمبيوتر تعرض أسماء النماذج المتاحة، ولا توجد علاقة مالك ثابتة بالشخص. لا ربط بالاسم أو التخمين.
6. **قدرات غير معايرة:** garment tags الخام ليست فلاتر مؤكدة؛ clusters التجريبية لا تُفتح تلقائيًا؛ group/equipment لها حدود الصور الحالية.
7. **الحالات القديمة:** لا يجوز تحويل نتائج قديمة بلا مصدر معروف إلى provenance كامل بالتشابه أو الشخص وحده؛ تُعرض المعلومات المتاحة بصراحة.
8. **لا افتراضات خلف الوعد البصري:** حفظ drafts لكل الأدوات، undo لكل merge، file operations عامة، arbitrary-step training resume ليست ضمانات حالية.

## 19. سيناريوهات قبول الـwireframes قبل high-fidelity

هذه مراجعات مسارات على الورق/في prototype، وليست ادعاء اختبارات للتطبيق.

- [ ] A01: جهاز بلا ربط PC وبصلاحية كاملة يبدأ Gallery ويرى الأصل غير المحلل.
- [ ] A02: إذن محدود/مرفوض ثم تغييره؛ الفارق عن لا نتائج فلتر واضح.
- [ ] A03: مجلد ← صورة ← تفاصيل ← شخص ← موديل ← رجوع متكرر يحفظ الأصل والمجلد والموضع.
- [ ] A04: صورة جماعية بها معروفان ومجهول وجسم بلا وجه؛ كل action يستهدف الظهور المقصود ولا يخلط owners.
- [ ] A05: فتح موديلات شخص داخل الصورة لا يعرض نموذج شخص آخر ولا DFM بلا علاقة.
- [ ] A06: صورة غير محللة ← تحليل صريح ← pairing عند الحاجة ← هوية/تعيين؛ التصفح لا يتوقف.
- [ ] A07: Reface من الصورة يجعلها target؛ من الشخص يملأ identity source؛ confirmation يفرق الاثنين.
- [ ] A08: فيديو/trim/reference identities وحالة legacy لا توحي target-box أو group/equipment support غير موجود.
- [ ] A09: شخص ← Dataset ← caption/exclusion/export ← تدريب متوقف/فاشل ← موديل محلي جاهز بعد تحقق فقط.
- [ ] A10: أكثر من موديل للشخص، موديل قديم بلا dataset link، وزن مفقود، ونتيجة قديمة بلا provenance.
- [ ] A11: Discover من جسم ← تشابه ← أصل ← مراجعة/شخص ← رجوع يحفظ المثال/المعيار/الموضع.
- [ ] A12: equipment shared وصحيح/مرفوض/manual؛ حفظ فئة pose/outfit واستبعاد عنصر؛ علامة تطابق تحتاج قرارًا.
- [ ] A13: رفض اقتراح ثم rescan/regroup؛ القرار وقفل التجميع يبقيان، و«غير متأكد» لا يصبح رفضًا.
- [ ] A14: شبكة/PC تتغير أثناء مهمة، manual pause سابق، lost job، تخزين ممتلئ أثناء الاستيراد؛ لا complete/ACK مبكر.
- [ ] A15: أصل حذف/فقد الإذن مع crop/نسخة مصدر باقية؛ labels لا تدعي أنها original.
- [ ] A16: حذف شخص/دمج/فصل/حذف موديل أو Dataset يظهر الأثر الصحيح دون undo مصطنع أو حذف أصل ضمني.
- [ ] A17: نقل أصول فعلي يعرض preview/conflicts/reconciliation؛ إلغاء لا يدعي استرجاع ما نُقل بالفعل.
- [ ] A18: Backup مشفر وInspect/Restore والنطاق/الاستبدال/فشل كلمة المرور؛ لا وعد بنسخ كل originals.
- [ ] A19: أي وظيفة في مصفوفة الاحتفاظ لها مدخل وفعل وحالة رجوع، حتى بعد إزالة Home/Jobs من الشريط.
- [ ] A20: الشاشات الأساسية بحجم هاتف صغير ونص كبير؛ الأزرار والـsheets تتمرر وتلتف بلا قص، والتفاصيل متاحة دون gesture فقط.

الانتقال إلى التصميم النهائي يتطلب مرور هذه السيناريوهات، وتثبيت سياسات الروابط/الدمج/الحذف التي تؤثر على شكل الشاشات. تنفيذ التطبيق والمحركات وترحيل البيانات يظل مرحلة لاحقة منفصلة.
